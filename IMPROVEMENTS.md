## 2026-10-19 — Аккаунты (E2E, локальный режим) + голубая тема (sw v25)
- Локальные аккаунты: имя, пароль (≥8), аватар (JPEG/WebP, уменьшается), дом (район/точка) с живым AQI, работа/учёба, избранное, настройки. PBKDF2-SHA256 310k + AES-GCM-256, в IndexedDB только шифротекст, ключ только в памяти; автоблокировка, «Заблокировать»/«Выйти», несколько аккаунтов, удаление, зашифрованный бэкап .tazaaba. Страница конфиденциальности (4 языка). Гостевой режим работает как прежде.
- Серверный режим (Supabase) готов в коде и включается заполнением SUPABASE_URL/SUPABASE_ANON_KEY в config.js; объекты изолированы префиксом: таблица taza_profiles, бакет taza-aba-avatars, RPC taza_delete_my_account (backend/schema.sql, backend/setup.sh с SUPABASE_REF для существующего проекта). Не включён: у выданного токена нет прав на запись (SQL read-only, нет auth_config_write/project_admin_write, создание проекта → 403).
- Голубая тема «Зелёная / Голубая» (светлая и тёмная), запоминается, контраст WCAG AA.
- Почему: просьба пользователя — личный кабинет без утечки данных и второй цветовой вариант.

## 2026-10-19 — Аккаунты 2: «Запомнить меня», код восстановления, привязка почты; «Транспорт и смог» v3 (sw v26)
- «Запомнить меня на этом устройстве» (по умолчанию включено): ключ данных хранится в IndexedDB как неизвлекаемый CryptoKey (exportKey → InvalidAccessError), автоматический вход после перезагрузки/перезапуска; «Выйти» и «Выйти на всех устройствах» (scope global в Supabase) стирают ключ; автоблокировка на запомненном устройстве выключена, включается отдельной галочкой. Компромисс описан на странице конфиденциальности (4 языка).
- Ключ данных теперь случайный (32 байта), обёрнут паролем и кодом восстановления (100 бит, показывается один раз). «Забыли пароль?» → код + новый пароль, данные сохраняются. Старые аккаунты: «Создать новый код» в настройках (перешифровка).
- Почта: в серверном режиме — привязка с подтверждением письмом (PKCE, ссылка на текущий адрес), вход по email, сброс пароля по ссылке (+ код восстановления, иначе «начать заново»), сессия Supabase persistSession. В локальном режиме поле выключено с пометкой «появится после подключения сервера» — без имитации проверки. В схеме добавлен столбец wk (обёртки ключа, шифротекст).
- Транспорт: причина «пустой карты» — цвет зависел от NO₂ CAMS; днём NO₂ низкий (перемешивание), а при сбое Open-Meteo все дороги были серыми #9aa, почти невидимыми на подложке. Теперь цвет по умолчанию — загруженность (оценка) = суточный профиль (будни/суббота/воскресенье) × размер города (по длине главных улиц OSM) × структура улицы (класс, полосы, maxspeed, центр, плотность перекрёстков, центральные артерии Бишкека), без зависимости от сети. Режимы «Пробки × NO₂» и «Только структура». Легенда, источник цвета, «Живые пробки» (TomTom, только при ключе и только Турция — КР в покрытии TomTom нет).
- Снимки OSM v4: + названные unclassified/residential улицы ≥250 м, maxspeed, oneway; по одному файлу на город, загружается только выбранный. Бишкек 4561 улица (было 1467).
- Профиль активности для оценки доли транспорта выровнен с профилем загруженности.
