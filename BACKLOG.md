# Таза Аба — бэклог идей

- Общий приёмник жалоб (например GitHub Issues / Telegram-бот → JSON в репозитории), чтобы мэрия видела жалобы всех жителей, а не одного устройства.
- Подключить наземные датчики (Кыргызгидромет / Clarity, если появится открытый API; Sensor.Community уже частично) в панель решений — сейчас CAMS ~40 км не различает районы Бишкека.
- Ежедневная автоматическая выгрузка CSV истории в репозиторий (GitHub Actions) — накопительный открытый архив, а не только 30 дней.
- Telegram-канал «прогноз смога на завтра» для школ и поликлиник (текст уже формируется в `#gov`).
- Слой «зоны центрального отопления» (OSM / открытые данные Бишкектеплосети) для точнее таргетированной замены угля.
- Реальные данные о пробках (TomTom/HERE ключ мэрии) вместо структурного индекса нагрузки; калибровка индекса по подсчётам машин, если мэрия их опубликует.
- Упростить снимок Стамбула (1,8 МБ) — объединять сегменты одной улицы.

- Живые пробки для КР: 2ГИС MapGL (ключ, проверить условия встраивания слоя пробок) или Яндекс JS API (ключ; пробки только на карте Яндекса). Для Турции — TomTom ключ (developer.tomtom.com).
- Серверный режим аккаунтов: нужен токен Supabase с правами записи (SQL, auth_config_write, project_admin_write).
- Зимы по годам: сравнение по районам имеет смысл только с наземными датчиками — CAMS (~40 км) даёт по Бишкеку ~2 разных значения на весь город (проверено 20.10). Отдельный срез «отопительный сезон» — если мэрия опубликует официальные даты.
- Наложить на график зим даты реальных мер (запуск газификации, запрет угля и т.п.) — только по официальным публикациям со ссылками.
- Памятка для акимата: добавить контакты и телефоны ответственных служб — только из официальных источников города; вариант на кыргызском для районных газет (формат A5).
- Памятка: если появятся данные наземных датчиков города, показывать их рядом с моделью CAMS (модель может заметно отличаться от наземных измерений, особенно при зимних инверсиях).
